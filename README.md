# AI VTuber System

配信コメントに自律的に応答し、コメントが無い時間も自分で話題を選んで喋り続ける、AI VTuber のための配信システムです。ローカル LLM とクラウド LLM のハイブリッド構成、階層化プロンプトと出所タグ付き記憶による「育つキャラクター」、TTS 連携、OBS ブラウザソース表示までを 1 つの Python アプリケーションでまかないます。

> **本パッケージにキャラクター設定と QLoRA 学習済みモデルは含まれません。**
> 同梱されているのはシステム本体（コード）と、記入例としてのサンプルキャラクター「Character1」の設定だけです。自分のキャラクターで動かすには、キャラクター設定と（必要なら）音声・モデルを各自で用意してください。手順は [docs/CHARACTER_GUIDE.md](docs/CHARACTER_GUIDE.md) を参照してください。

## 何ができるか

- **配信コメントへの応答**: YouTube Live（pytchat / YouTube Data API）、Twitch、ツイキャスのコメントを取得し、優先度順に読み上げて返答します。
- **自律発話**: コメントが途切れると、話題プランナが「記憶・ニュース・調べもの」から話題を選んで喋り続けます。視聴者からの事実質問（「〜って何？」「今日の天気は？」など）は Web 検索で調べてから、資料に基づいて後から回答します。
- **複数キャラクターの掛け合い**: キャラクターを 2 体以上並べると、誰が答えるか・相方がどう受けるかを演出層が決める掛け合い配信になります（1 体だけの単独配信も可能です）。
- **育つキャラクター**: プロンプトは L0a 初期設定（不変）／L0b 育つ信条／L1 自己物語／L2 現在の自分／L3 状況の 5 層構造。意見・意図・選好は出所タグ（経験・教示・調査・推論・夢）付きでキャラクターごとに保存され、アイドル時の自律思考と夜間の睡眠時統合で少しずつ育ちます。
- **ハイブリッド LLM**: 待機・掛け合いなどの急がない生成はローカル LLM（Ollama / LM Studio）へ、コメント返答など即応が要る生成はクラウド LLM（Gemini / Claude / OpenAI 系）へ振り分けます。クラウド側が不調なときはローカルで受けるため、配信は止まりません。
- **音声合成**: Irodori-TTS（参照音声によるボイスクローン）または VOICEVOX に対応。文単位のストリーミング合成で、生成と発話を並行させます。感情に応じてボイスを切り替えることもできます。
- **アバター表示**: VRM / Live2D / 動画アバター（モーション動画カタログ）に対応し、OBS のブラウザソースとして表示します。字幕ページも同梱しています。
- **ローカル対話モード**: 配信をしなくても、ブラウザのチャット画面やマイク音声認識（faster-whisper）でキャラクターと 1 対 1 で会話できます。
- **Unity 連携**: 同梱の Unity プロジェクトと C# スクリプトで、VRM アバターを Unity 側で描画する構成も選べます。
- **人格 QLoRA（任意）**: キャラクター設定のセリフ例や会話履歴から学習データを作り、QLoRA で口調をモデルに焼き込むパイプラインを内蔵します（ダッシュボードから実行可能）。学習済みモデル自体は本パッケージに含まれません。

## 動作要件

- **OS**: Windows 10 / 11 を想定（起動バッチ同梱。Python が動く他 OS でも `run.py` から起動できます）
- **Python**: 3.11 以上
- **ローカル LLM**: Ollama または LM Studio のいずれか（クラウド LLM のみでも動作しますが、ハイブリッド構成が前提の設計です）
- **TTS**: Irodori-TTS サーバ、または VOICEVOX（どちらも別プロセスで用意します）
- **GPU**: ローカル LLM・TTS を快適に動かす場合に推奨。人格 QLoRA の学習には CUDA 対応 GPU が必要です

## クイックスタート（最短手順）

1. 依存パッケージを入れます。

   ```bash
   pip install -r requirements.txt
   ```

2. ローカル LLM を用意します（Ollama の場合）。

   ```bash
   ollama pull llama3.1:8b
   ```

   `config.yaml` の `llm` セクションで、使用するバックエンドとモデル名を合わせてください（既定では LM Studio が主系です）。

3. TTS を用意します。Irodori-TTS サーバを配置し、`config.yaml` の `tts.irodori_server.dir` にそのフォルダを指定すると、本体起動時に自動で立ち上がります。VOICEVOX を使う場合は `tts.primary: voicevox` に切り替えます。

4. API キーが必要な機能（YouTube Data API フォールバック、クラウド LLM、Web 検索）を使う場合は、`.env.example` を `.env` にコピーして該当項目だけ記入します。

5. 起動します。

   ```bat
   start.bat
   ```

   または:

   ```bash
   python run.py
   ```

6. ブラウザでダッシュボード（http://127.0.0.1:9000）を開きます。まず `/chat` のローカルチャットで会話が成立することを確認し、次に OBS へ `/avatar` と `/subtitle` をブラウザソースとして追加してください。配信の始め方は [docs/SETUP.md](docs/SETUP.md) にまとめています。

同梱の Character1 は記入例のサンプルキャラクターです。そのまま起動すればサンプル設定で喋りますが、実運用では自分のキャラクターに差し替えてください。

## 注意事項

- **QLoRA 学習済みモデル・キャラクター設定は含まれません。** `models/` 以下にモデルを配置し、キャラクター設定は `backend/llm/prompts/characters/` 以下に各自で用意してください（サンプルの Character1 が記入例になっています）。
- **UniVRM は同梱していません。** Unity プロジェクト（`AIVunity/`）で VRM を扱うには、UniVRM を UPM 経由で別途導入してください。
- `tools/llama.cpp/` は GGUF 変換用に同梱した llama.cpp プロジェクトの部分コピーで、それぞれのライセンスに従います。
- API キーは `.env` と環境変数で管理し、`config.yaml` には環境変数名（`api_key_env`）だけを書く設計です。`.env` をリポジトリにコミットしないでください（`.gitignore` で除外済み）。
- 配信枠の作成・開始・終了といった YouTube 側の操作は YouTube Studio で行います。本システムが担うのはコメント取得と発話・表示です。
